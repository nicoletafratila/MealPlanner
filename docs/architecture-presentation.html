MealPlanner

Plan meals. Share recipes. Shop smarter.
A multi-service .NET application — Blazor Server web app + .NET MAUI mobile app,
backed by three independent APIs and a shared SQL Server database.

What it does

📖 Recipe Book

Recipes, ingredients, units, categories, and per-recipe statistics.

🗓️ Meal Planning

Assign recipes to days/meals to build out a weekly plan.

🛒 Shopping Lists

Auto-generated from a meal plan, grouped by shop.

🤝 Sharing

Share a recipe, product, or shop with another user, categories included.

One account, every device

🌐 Web app — Blazor Server + MudBlazor, responsive, port 7093
📱 Mobile app — .NET MAUI, Android & Windows, Page+ViewModel MVVM
🔐 Identity — Duende IdentityServer, JWT + cookie auth
📝 Audit trail — account activity logged and reviewable

System architecture

All three APIs authenticate via Identity.Api and share one EF Core DbContext. RecipeBook.Api and MealPlanner.Api call each other directly over HTTP for cross-domain lookups.

Per-domain library structure

Identity, RecipeBook, and MealPlanner each follow the same layering:

SuffixPurpose
*.Data.EntitiesEF Core entity classes
*.Data.ProfilesAutoMapper profiles
*.Data.TableConfigurationsIEntityTypeConfiguration<T> classes
*.Services.HttpTyped HttpClient wrappers used by the frontends
*.SharedDTOs and route constants shared between API and consumers

Plus cross-cutting Common.* libraries: Core (DI/Startup), DataContext, Repository, Models, Pagination, Http, Services, Validators, Constants, UI.

Handlers never throw outward — they return CommandResponse.Success() / Failed(message).
Controllers always reply 200 OK; callers check .Succeeded. Each feature = Command/Query + Validator + Handler, 3 files, one folder.

Built for maintainability

✅ Mirror test projects — every project has a matching .Tests project, NUnit + Moq
🗄️ Centralized logging — Serilog to console, rolling file, and SQL Server, consistent across all 3 APIs
🌍 Localization-ready — all user-facing strings in .resx resources, not hardcoded
🔒 Policy-based auth — every endpoint requires an explicit authorization policy + role
